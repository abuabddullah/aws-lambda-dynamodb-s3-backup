Serverless পাইপলাইন: API → Lambda → DynamoDB → Lambda → S3

প্রতিটা ধাপে তিনটা জিনিস আছে: কী করবেন, কেন করছেন, আর ভিডিওতে কী বলবেন। কাজ শেষ হলে বাঁ পাশের বক্সে টিক দিন। আপনার ব্রাউজার টিকগুলো মনে রাখবে।

১. আপনার মানগুলো বসান

এখানে মান বসালে নিচের সব IAM পলিসি আর environment variable নিজে থেকেই আপডেট হবে। তারপর Copy করে AWS-এ পেস্ট করলেই হবে।

এই মানগুলো শুধু আপনার ব্রাউজারে থাকে, কোথাও পাঠানো হয় না। Bucket নাম পুরো দুনিয়ায় ইউনিক হতে হবে: ছোট হাতের অক্ষর, সংখ্যা আর হাইফেন, ৩–৬৩ অক্ষর।

নতুন AWS কনসোল (নভেম্বর ২০২৬)অ্যাসাইনমেন্টের README পুরনো কনসোল দেখে লেখা। যেখানে নাম বা মেনু বদলেছে, সেখানে এই গাইডে নতুন নামটা দেওয়া আছে: Lambda → "Create Event Function" (architecture আর role এখন toggle), CloudWatch → Logs → Log Management, আর টেস্ট রেজাল্টে সরাসরি logs ↗ লিংক।

২. ভিডিও রেকর্ডিং প্ল্যান

রেকর্ডের আগে প্রাইভেসি এই কাজে Account ID স্ক্রিনে বেশ কয়েক জায়গায় আসবে: উপরের ডানদিকের অ্যাকাউন্ট মেনু, IAM পলিসির JSON, table ARN, Lambda-র function ARN। ক্যামেরা চালু থাকা অবস্থায় অ্যাকাউন্ট মেনু খুলবেন না। Account ID আগে থেকে কপি করে এই পেজে বসিয়ে রাখুন। এডিটের সময় পলিসি JSON আর ARN-এর জায়গাগুলো blur করে দেবেন। নিচে যে ধাপে blur লাগবে, সেখানে BLUR চিহ্ন দেওয়া আছে। Access key বা password কখনোই স্ক্রিনে আনবেন না।
রেকর্ডিং সেটআপ
  • শুধু AWS কনসোলের জন্য আলাদা একটা Chrome window রাখুন। বাড়তি ট্যাব আর বুকমার্ক বার বন্ধ রাখলে ফ্রেম পরিষ্কার দেখাবে।
  • ব্রাউজার zoom ১১০–১২৫% রাখুন, তাহলে মোবাইলেও লেখা পড়া যাবে।
  • এই গাইড পেজটা দ্বিতীয় মনিটরে বা ফোনে খোলা রাখুন, রেকর্ডিং ফ্রেমের বাইরে।
  • পুরোটা এক টানে রেকর্ড না করে প্রতিটা Part আলাদা ক্লিপে রেকর্ড করুন। কোথাও ভুল হলে শুধু সেই ক্লিপটা আবার করতে হবে।
  • যেখানে অপেক্ষা করতে হয় (table Active হওয়া, Scheduler-এর রান), সেখানে রেকর্ডিং pause করুন, অথবা এডিটে কেটে দিন।

৩. আর্কিটেকচার

ভিডিওতে বলুন (S0) "আজ আমরা একটা serverless পাইপলাইন বানাব, যেখানে কোনো সার্ভার চালু রাখতে হবে না। প্রথম Lambda একটা পাবলিক API থেকে ১০ জন ইউজার এনে DynamoDB-তে রাখবে। দ্বিতীয় Lambda প্রতি ২ মিনিট পরপর পুরো টেবিলটা পড়বে আর S3-তে একটা নতুন JSON ফাইল লিখবে। কে কখন চালাবে সেটা ঠিক করবে EventBridge Scheduler। প্রতিটা Lambda নিজের IAM role নিয়ে চলবে, যাতে শুধু যতটুকু দরকার ততটুকু পারমিশন পায়।"
মূল ধারণা এখানে খেয়াল করার মতো ব্যাপার হলো, কোডে কোথাও access key লেখা নেই। Lambda চালু হলে AWS তাকে তার execution role-এর অস্থায়ী credential দিয়ে দেয়, আর boto3 সেটা নিজে থেকেই খুঁজে নেয়। তাই কোনো Lambda কী করতে পারবে সেটা কোড ঠিক করে না, IAM পলিসি ঠিক করে।

Part A — DynamoDB আর S3 সেটআপ

Step 1

Region বাছাই করুন

▶
  1. AWS কনসোলের উপরের ডানদিকে Region selector থেকে US East (N. Virginia) — us-east-1 বেছে নিন।
  2. পুরো কাজের সময় এই Region আর বদলাবেন না।
কেনDynamoDB table, Lambda আর Scheduler, এগুলো সবই একটা নির্দিষ্ট Region-এর রিসোর্স। Lambda #2 ভিন্ন Region-এ থাকলে তার Region-এ টেবিলটা খুঁজে পাবে না, ফলে ResourceNotFoundException আসবে। আর Scheduler তার target বাছাইয়ের তালিকায় শুধু নিজের Region-এর Lambda-ই দেখায়।
ভিডিওতে বলুন"সবকিছু একই Region-এ, us-east-1-এ রাখছি। Region আলাদা হলে এক সার্ভিস আরেকটাকে খুঁজে পাবে না।"
Step 2

DynamoDB table তৈরি করুন

▶
  1. DynamoDB → Tables → Create table খুলুন।
  2. Table name দিন jsonplaceholder-users।
  3. Partition key দিন id, আর টাইপ বেছে নিন Number। ডিফল্টে String থাকে, সেটা বদলাতে হবে।
  4. Sort key খালি রাখুন। Table settings-এ Default রাখুন, অথবা Customize করে On-demand বেছে নিন।
  5. Create table চাপুন, তারপর Status Active হওয়া পর্যন্ত অপেক্ষা করুন। এই সময়টা রেকর্ডিং pause রাখুন।
কেন NumberAPI যে JSON পাঠায় সেখানে "id": 1 একটা সংখ্যা। boto3 এই সংখ্যাকে DynamoDB-র Number টাইপে পাঠায়। টেবিলের key যদি String হয়, তাহলে টাইপ মিলবে না আর PutItem ValidationException দেবে। Partition key-র কাজ হলো প্রতিটা আইটেমকে আলাদাভাবে চেনানো, অনেকটা SQL-এর primary key-র মতো। এর বাইরে name, email, address-এর মতো বাকি ফিল্ডের জন্য আগে থেকে কোনো schema বানাতে হয় না। এটাই NoSQL-এর সুবিধা।
ভিডিওতে বলুন"Partition key হিসেবে id দিচ্ছি, আর টাইপ রাখছি Number, কারণ API থেকে id সংখ্যা হিসেবেই আসে। বাকি ফিল্ডগুলোর জন্য কোনো কলাম বানাতে হচ্ছে না, DynamoDB নেস্টেড JSON সরাসরি রাখতে পারে।"
স্ক্রিনশট01-dynamodb-table.png: টেবিলের Overview, যেখানে Partition key id (Number) আর Status Active দেখা যায়। BLUR: টেবিলের ARN।
Checkpoint A: jsonplaceholder-users Active, partition key id (Number)।
Step 3

Private S3 bucket তৈরি করুন

▶
  1. S3 → Buckets → Create bucket খুলুন।
  2. Bucket type রাখুন General purpose।
  3. নাম দিন YOUR_UNIQUE_BUCKET_NAME, আর Region us-east-1।
  4. Block all public access চালু রাখুন, এটা ডিফল্টেই চালু থাকে।
  5. Default encryption SSE-S3 যেমন আছে তেমনই রাখুন। এরপর Create bucket চাপুন।
  6. backups/ ফোল্ডার আলাদা করে বানাতে হবে না।
কেনS3-তে আসলে কোনো "ফোল্ডার" নেই। প্রতিটা object-এর key একটা লম্বা স্ট্রিং, যেমন backups/2026-11-18/users-....json। কনসোল / দেখে সেগুলোকে ফোল্ডারের মতো সাজিয়ে দেখায়, তাই প্রথম ফাইল লেখা হলেই ফোল্ডারটা দেখা যাবে। ব্যাকআপে ইউজারদের ইমেইল আর ফোন নম্বর থাকে, তাই bucket private রাখা জরুরি।
ভিডিওতে বলুন"Block Public Access চালু রাখছি, কারণ ব্যাকআপে ইউজারদের ব্যক্তিগত তথ্য থাকবে। backups ফোল্ডার আলাদা করে বানাচ্ছি না। S3-তে ফোল্ডার আসলে key-এর একটা prefix মাত্র, প্রথম ফাইল লেখা হলে এটা নিজে থেকেই দেখা যাবে।"
Checkpoint B: us-east-1-এ একটা private S3 bucket আছে।

Part B — Lambda #1: API থেকে DynamoDB-তে

Step 4

Lambda #1 তৈরি করুন

▶
  1. Lambda → Functions → Create function → Author from scratch খুলুন।
  2. Function name দিন import-jsonplaceholder-users।
  3. Runtime দিন Python 3.12 বা তার চেয়ে নতুন ভার্শন (যেমন 3.15)।
  4. নতুন কনসোল ("Create Event Function"): Additional settings-এ ARM64 architecture = Off রাখুন, যার মানে x86_64। Custom execution role = Off রাখুন, যার মানে basic permission-সহ নতুন role। VPC = Off। Durable execution আর EC2 capacity provider-ও Off থাকবে। তারপর Create Event Function চাপুন।
  5. পুরনো কনসোল: Architecture x86_64, Execution role Create a new role with basic Lambda permissions, তারপর Create function।
  6. Configuration → General configuration → Edit থেকে Memory 128 MB আর Timeout 0 min 30 sec দিয়ে Save করুন।
কেনডিফল্ট timeout মাত্র ৩ সেকেন্ড। ইন্টারনেট থেকে API কল করে তারপর ১০ বার DynamoDB-তে লিখতে কখনো কখনো এর চেয়ে বেশি সময় লাগে, তাই ৩০ সেকেন্ড দিচ্ছি। "Basic permissions" role-এ শুধু CloudWatch-এ লগ লেখার পারমিশন থাকে, DynamoDB-তে লেখার পারমিশন থাকে না। সেটা পরের স্টেপে যোগ করব।
ভিডিওতে বলুন"Timeout ৩ থেকে বাড়িয়ে ৩০ সেকেন্ড করছি, কারণ এই ফাংশন বাইরের একটা API কল করবে। নতুন role-টায় এখন শুধু লগ লেখার পারমিশন আছে।"
Step 5

Lambda #1-কে DynamoDB-তে লেখার পারমিশন দিন

▶
  1. Lambda #1-এ Configuration → Permissions খুলে Role name লিংকে ক্লিক করুন। IAM নতুন ট্যাবে খুলবে।
  2. Add permissions → Create inline policy → JSON বেছে নিন।
  3. এডিটরে যা লেখা আছে সব মুছে নিচের JSON পেস্ট করুন। এটা আপনার দেওয়া মান দিয়ে আগেই তৈরি হয়ে আছে।
  4. Next চাপুন, Policy name দিন AllowPutDemoUsers, তারপর Create policy।
  5. Role-এর পলিসি লিস্টে AWSLambdaBasicExecutionRole... আছে কিনা দেখুন। ওটা যেমন আছে থাকবে।


কেন (Least privilege)এই পলিসি একটাই কাজের অনুমতি দেয়: একটা নির্দিষ্ট টেবিলে PutItem। এই ফাংশন টেবিল থেকে পড়তে পারবে না, কিছু ডিলিট করতে পারবে না, অন্য কোনো টেবিলেও হাত দিতে পারবে না। এর বদলে AdministratorAccess দিলে কোডে একটা বাগ বা একটা ক্ষতিকর dependency থাকলেই পুরো অ্যাকাউন্ট ঝুঁকিতে পড়ত। পারমিশন যত কম, কিছু ভুল হলে ক্ষতিও তত কম (blast radius ছোট থাকে)।


BLURএই JSON-এ আপনার Account ID আছে, তাই এডিটে এই অংশটা blur করবেন।


ভিডিওতে বলুন"AdministratorAccess দিলে কাজ হয়ে যেত ঠিকই, কিন্তু সেটা ভুল অভ্যাস। এই ফাংশনের দরকার শুধু একটা টেবিলে PutItem, তাই ঠিক এইটুকুই দিচ্ছি। একে বলে least privilege।"

Step 6

ভিডিওতে বলুন"কোডে টেবিলের নাম লেখা নেই, সেটা আসে environment variable থেকে। Handler-এর মানে হলো কোন ফাইলের কোন ফাংশন চালানো হবে।" (এরপর নিচের কোড অংশ থেকে কোডটা ২–৩ লাইনে ব্যাখ্যা করুন।)

কেন {}এই ফাংশন event থেকে কিছুই পড়ে না, তাই একটা খালি JSON পাঠালেই চলে। Test চাপলে Lambda একবার invoke হয়। কোডের প্রতিটা print() নিজে থেকেই CloudWatch Logs-এ চলে যায়, কারণ role-এ AWSLambdaBasicExecutionRole আছে।


ভিডিওতে বলুন"Status 200, saved_count 10। এবার CloudWatch-এ দেখি। কোডে যত print() আছে, সব এখানে লাইন ধরে চলে এসেছে। START, END আর REPORT লাইনগুলো Lambda নিজে লেখে। REPORT লাইনে দেখা যায় কত সময় লেগেছে আর কতটা মেমরি খরচ হয়েছে।"

কেন এই দুটো১. dynamodb:Scan দিয়ে শুধু একটা টেবিল পড়া যাবে। ২. s3:PutObject দিয়ে শুধু backups/* prefix-এর ভেতরে লেখা যাবে, bucket-এর অন্য কোথাও না। Delete, GetObject বা টেবিল বদলানোর মতো কোনো পারমিশন এখানে নেই। খেয়াল করুন, S3-এর ARN-এ Region বা Account ID থাকে না (arn:aws:s3:::bucket/key), কারণ bucket-এর নাম পুরো দুনিয়ায় ইউনিক।


BLURDynamoDB ARN-এর Account ID blur করবেন।


ভিডিওতে বলুন"এই ফাংশন টেবিল পড়বে আর S3-এর শুধু backups ফোল্ডারে লিখবে। ডিলিট করার পারমিশন ইচ্ছা করেই দিইনি। কোডে বাগ থাকলেও সে কোনো ব্যাকআপ মুছতে পারবে না।"

Step 13
EventBridge Scheduler-এ schedule তৈরি করুন
▶


  1. Amazon EventBridge → Scheduler → Schedules → Create schedule খুলুন।
    2. 

  2. Name দিন dynamodb-backup-every-2min, আর Group রাখুন default।
    3. 

  3. Occurrence Recurring, Schedule type Rate-based, Rate 2 minutes।
    4. 

  4. Flexible time window Off করুন, তারপর Next।
    5. 

  5. Target-এ AWS Lambda Invoke বেছে নিয়ে Function দিন export-dynamodb-to-s3। Payload {}, তারপর Next।
    6. 

  6. Schedule state Enabled রাখুন। Permissions-এ বেছে নিন Create new role for this schedule।
    7. 

  7. Next দিয়ে Review করুন, তারপর Create schedule।


কেন দুটো আলাদা roleএখানে দুটো আলাদা প্রশ্ন আছে। Lambda-কে চালু করার অনুমতি কার আছে? এর উত্তর Scheduler-এর role, যেখানে lambda:InvokeFunction পারমিশন থাকে। চালু হওয়ার পর Lambda কী কী করতে পারবে? এর উত্তর Lambda-র execution role, যেখানে Scan আর PutObject থাকে। Scheduler নিজে DynamoDB বা S3-তে কিছু করে না, শুধু সময়মতো Lambda-কে ডাকে।

Flexible window Off রাখলে Scheduler যতটা সম্ভব ঠিক সময়ে চালাবে। চালু রাখলে AWS লোড ছড়িয়ে দিতে কয়েক মিনিট পরে চালাতে পারে।


ভিডিওতে বলুন"Scheduler-এর জন্য আরেকটা role তৈরি হচ্ছে। এর কাজ শুধু Lambda-কে invoke করা। Lambda চালু হওয়ার পর কী করতে পারবে, সেটা ঠিক করে Lambda-র নিজের role। দুটো আলাদা দায়িত্ব, তাই দুটো আলাদা role।"


স্ক্রিনশট10-scheduler.png: Schedule-এর detail পেজ, যেখানে Enabled আর rate(2 minutes) দেখা যায়।





Step 14
নিজে নিজে চলছে কিনা যাচাই করুন
▶


রেকর্ডিংএখানে রেকর্ডিং pause করে ৫–৬ মিনিট অপেক্ষা করুন, যাতে অন্তত ২–৩টা রান হয়ে যায়। এডিটে লিখে দিতে পারেন "৬ মিনিট পর"।


  1. S3-তে backups/তারিখ/ খুলে Refresh চাপুন। আগের দুটো ম্যানুয়াল ফাইলের পরে মোটামুটি ২ মিনিট পরপর নতুন ফাইল আসছে কিনা দেখুন।
    2. 

  2. CloudWatch → Logs → Log Management → Log groups থেকে /aws/lambda/export-dynamodb-to-s3 খুলে নতুন log stream বা request গুলো দেখুন।
    3.

▶


  • Scan কোনো snapshot নেয় না। Scan চলার মধ্যেই কেউ টেবিলে লিখলে JSON-এ কিছু আইটেম পুরনো আর কিছু নতুন অবস্থায় আসতে পারে।

ভিডিওতে বলুন"এটা শেখার জন্য ভালো একটা export, কিন্তু আসল ব্যাকআপ না। আসল প্রজেক্টে PITR চালু করতাম, আর কতক্ষণের ডেটা হারানো চলবে (RPO) এবং কত দ্রুত ফিরতে হবে (RTO), সেই হিসেব অনুযায়ী ব্যাকআপ প্ল্যান করতাম।"
